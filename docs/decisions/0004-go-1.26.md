# ADR 0004 - Go 1.26 minimum and current dependency tags

**Date:** 2026-10-22 - **Status:** Accepted - **Decider:** operator

Supersedes the Go-minimum bullet of ADR 0003. Everything else in ADR 0003 (restic 0.19.1, rclone 1.75.1, lint, CI, layout) stands.

## Decision

- **Go 1.26** minimum. `go.mod` carries `go 1.26.0` (`go get` raised the bare `1.26` to `1.26.0` because the new dependency tags declare it; there is no `toolchain` line). CI keeps `go-version-file: go.mod`, so it resolves the newest 1.26.x on its own.
- The three modules ADR 0003 held back move to their newest tags:

| Module | Before | After |
|---|---|---|
| `modernc.org/sqlite` | v1.59.0 | v1.61.0 |
| `golang.org/x/crypto` | v0.55.0 | v0.58.0 |
| `golang.org/x/sys` | v0.47.0 | v0.49.0 |

- Indirect modules moved with them: `modernc.org/libc` v1.75.7 to v1.79.0, `github.com/dustin/go-humanize` v1.0.1 to v1.1.0, `github.com/ncruces/go-strftime` v1.0.0 to v1.1.0.
- The console image builds with `golang:1.26.10-bookworm` (`deploy/compose/console.Dockerfile`, `docker-compose.yml`, `.env.example`).

## Why

The older pins were an artefact of the Go 1.25 minimum in ADR 0003: they were the newest tags that did not require Go 1.26, chosen only to stay inside that minimum. For a security product, staying current on the SQLite driver (it parses every console record) and `x/crypto` (key derivation, AEAD, password hashing) matters more than keeping distribution packagers on Go 1.25. `CGO_ENABLED=0` and the no-cgo SQLite rule are unchanged.

## Consequences

- Packagers and contributors need Go 1.26 or newer; `CONTRIBUTING.md` says so.
- CI resolves Go 1.26.x from `go.mod` on the Ubuntu and Windows runners.
- The console image builds with `golang:1.26.10-bookworm`; the tag was confirmed on Docker Hub on the decision date. Bump it with each Go patch release.
- Future dependency bumps are no longer capped by the toolchain; ordinary patching cadence applies.
