# Competitor feature sweep: Cove, MSP360, IDrive (Windows workstation backup)

Clean-room sweep for CryoBackup. Public sources only: vendor documentation, pricing pages, press releases, vendor blogs, review sites. No binaries, no bundles, no logins. Compiled 2026-10-20.

Conventions used in every FEATURE LIST table:

- `area` is one of: agent / console / storage / alerting / restore / security / deployment / reporting / multi-tenant / billing
- `priority` is a guess for an MSP workstation product: **must** / **should** / **could**
- Anything not confirmed from a vendor-owned page is marked `[unverified]` or `[competitor claim]` in notes. Fetches that failed are listed in the SOURCES table so you know what was not read.

## 1. N-able Cove Data Protection (formerly SolarWinds Backup / MSP Backup / "Backup Manager")

Cove is the vendor the operator remembers fondly. What made it good then still describes the product: cloud-first, incremental-forever with block-level TrueDelta, optional local LocalSpeedVault for LAN-speed restores, one dashboard with exception-driven views, and recovery proof (Standby Image / Recovery Testing) with boot screenshots. The console has been rebuilt ("Enhanced Device Properties", Retention Policies replacing Products/Archiving, Notification Service), so the current product is closer to "what he liked" than the legacy RMM-integrated Managed Online Backup.

### 1.4 DESIGN LESSONS

Adopt:
1. **Exception-first dashboard with clickable summary rings.** Four rings (asset mix, last status, backup age, cloud tenants) that filter the grid, plus saved views and the "Unsuccessful backups" default view. The age ring ("< 24 h / 24-48 h / > 48 h") is the single most important widget for a sole operator: it turns silence into a visible bucket.
2. **Retention as a declarative policy object** assigned per device/customer: intra-daily N days, last-of-day N days, last-of-week/month/year N, with a calendar preview and the rule "last successful session is never pruned". Simple to reason about, easy to unit-test.
3. **Per-device Audit + History + Errors tabs** in one side panel, with session flags (A/S/C/L) and compressed-transfer-size per session. Every "why did this happen" question is answerable without SSH.
4. **Managed-encryption-by-default with a Security Officer gate.** Keys held by the service; a privileged role issues 24-hour one-time passphrases. Avoids the lost-key catastrophe while keeping an audit trail.
5. **Multi-use, site-scoped silent installer** that pre-binds customer, retention policy and profile. Deployment via any RMM is just "run this exe"; the "24 Hour RPO" default profile means a freshly installed device is already compliant.

Avoid:
1. **No native "no backup in N hours" alert.** Cove's Notification Service only fires on Failed / Completed with errors; a device that silently stops reporting is only caught by a scheduled report or a human looking at the age ring. CryoBackup must alarm on silence (the project's Synology 18-day rule).
2. **Reporting caps (10 columns x 200 rows, external opt-in with 48 h expiry, SES/SPF setup).** Fine for N-able, hostile to a one-person shop. Keep reports uncapped and the sender simple (SMTP2Go).
3. **Vendor-cloud-only storage and unpublished overage.** Fair-use pooling plus an unlisted $/TB overage is the thing MSPs complain about. Keep BYO/local storage first-class.

## 2. MSP360 Managed Backup (formerly CloudBerry; Windows Backup Agent)

MSP360 is the "bring your own storage" console: a SaaS Management Console (`mspbackups.com`) plus a Windows Backup Agent that writes to S3/Azure/Wasabi/B2/MinIO/local. Two backup formats coexist (legacy file-versioning format and the "new backup format" with generations, GFS, Forever Forward Incremental, Object Lock, client-side dedup). The console bundles optional RMM and Connect agents.

### 2.4 DESIGN LESSONS

Adopt:
1. **"Overdue" as a first-class plan state** with two independent triggers ("didn't run on schedule", "no success in N h/d"), a Computers filter, an email ("No successful backup within threshold"), and a ticket trigger. Also the status vocabulary Missed Run / Unexpectedly Closed / Interrupted -- these name the silent failure modes precisely.
2. **Calendar-matrix Backup History** (one cell per plan per day, Last vs Worst, Issue Only, CSV export). For a sole operator this is the fastest way to see "has this laptop backed up every day this month".
3. **Per-tenant policy overrides with inherit** (global -> company -> computer) for notifications and agent feature toggles (hide encryption option, VSS default, allow data deletion, allow pre/post scripts). Tiny UI, big operational payoff.
4. **BYO storage with provider-aware retention** (Intelligent Retention stretching "Keep backups for" to the bucket's minimum-storage term). CryoBackup targeting UrBackup/local + S3-compatible should encode the same economics.
5. **Sandbox vs Public agent builds + Force Update to selected machines.** A staged ring for agent upgrades is cheap to implement and prevents fleet-wide regressions.

Avoid:
1. **Two coexisting backup formats with different retention semantics, and customer-held encryption passwords with no escrow.** Half of MSP360's docs are caveats about which format supports what; lost plan passwords are unrecoverable. Pick one engine; escrow keys server-side with a privileged role.
2. **Computer -> User -> Company indirection.** Every machine must be bound to a "backup user" account (`cbb.exe addAccount`), and deletions cascade through users. One object (device) under one customer is enough for workstations.
3. **Reports in HTML/CSV only and branding/custom-domain behind extra licenses.** Produce a clean per-customer PDF/HTML without an upsell, and don't gate the sender address.

### 3.4 DESIGN LESSONS

Adopt:
1. **Explicit laptop semantics**: a 30-minute grace window for missed slots, a "run missed backup on power-on" switch, a battery-percentage floor, wake-from-sleep option, and Auto-pause throttling when the PC is in use. These are exactly the workstation edge cases Cove and MSP360 leave undocumented.
2. **Daily immutable snapshot + "restore as of date"** on top of per-file versions. The user-facing mental model ("show me my laptop as it was last Tuesday") is simpler than restore points/generations, and compliance-mode immutability covers ransomware without GFS complexity.
3. **Published, opinionated default exclusion list** with a one-click "include system and hidden files". Make the list visible and editable in the console, and default `.ost`, VM images and `C:\Windows` out for the workstation SKU.
4. **Percentage-based failure thresholds** ("Notify as Failure when failed files > 5 %", "missing files > N %"). Workstation backups routinely hit a handful of locked files; a tolerance avoids crying wolf while still catching real breakage.
5. **Native PDF/Excel reports with Alerts / Daily / Weekly / Summary tabs** and a device lifecycle with Block and Archive (keep data restorable, keep license) states.

Avoid:
1. **Private-key reset = delete everything.** The cliff between "we hold the key" and "you hold the key and if you lose it we wipe the account" is too sharp. Offer managed keys by default with a privileged export, as Cove does.
2. **Alerts configured per computer and pushed, instead of a central rule engine.** There is no console-wide "any device silent > 48 h" rule, no audit log, no API. For an MSP, alerting must be a server-side policy evaluated against all devices.
3. **Three overlapping product lines (Business dashboard, IDrive 360, BMR partner console) with different consoles and conflicting documented limits** (30 vs 50 versions, 2 / 5 / 10 TB quotas across cached pages). One console, one documented limit per feature.
